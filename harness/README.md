# harness — детерминированный слой харнесса Claude Code

TypeScript под Node ≥ 24 без сборки и без `node_modules`. Зачем контур и как он разложен — корневой `README.md`
репозитория; здесь — устройство слоя, выключатели, границы и проверки.

## Подключение

```bash
sh harness/install.sh                # найти Node >= 24 и тулчейн TypeScript, записать ~/.claude/env/harness.env, симлинк ~/.claude/harness
sh harness/install.sh --ensure-node  # Node >= 24 нет — скачать официальную сборку в ~/.claude/env/node/<версия>/ (sha256 сверяется);
                                     # PATH, nvm и системный node других проектов не трогаются
~/.claude/harness/bin/run scripts/toolchain.ts --install   # TypeScript с lib.*.d.ts и @types/node ровно по TOOLCHAIN.lock (integrity каждого пакета + sha256 точки входа), кеш ~/.cache/claude-harness
```

Сессия в репозитории всегда под харнессом: `.claude/settings.json` подключает события через шим
`.claude/bin/hook`. Шим отдаёт событие user-level харнессу, только если `~/.claude/settings.json` привязывает
именно это событие к `harness/bin/hook` (один `grep`); иначе запускает харнесс чекаута сам — одного симлинка
`~/.claude/harness` для отказа мало, его ставит и авто-установка Node. Тот же файл задаёт
`CLAUDE_HARNESS_AUTO_NODE=1`: на старте сессии без Node ≥ 24 шим вызывает `install.sh --ensure-node` и
перезапускается; без сети остаётся сигнал «harness inactive».

`settings.v4.json` — блок `hooks` для `~/.claude/settings.json`; `settings.repo.v4.json` — для `.claude/settings.json`
репозитория (вход через `.claude/bin/hook`).

Барьер, который не отработал, не пропускает: Node ≥ 24 не найден или рантайм упал с кодом не 0/2 — на
`PreToolUse` шим отвечает `ask` там, где человек видит вопрос (`default`, `acceptEdits`, `plan`), и `deny` в
`auto`, `bypassPermissions`, `dontAsk`; режим берётся из payload. На остальных событиях без рантайма шим молчит
и один раз за сессию печатает `systemMessage`. `CLAUDE_HARNESS_UNKNOWN` перекрывает режим на сессию: `ask`,
`deny` или `note` — примечание в `additionalContext` вместо решения.

## Как устроено

| Путь | Роль |
|---|---|
| `bin/hook <event>` | единственная точка входа: пин Node (`$CLAUDE_HARNESS_NODE` → `harness.env` → старший v24+ из `~/.nvm/versions/node` и `~/.claude/env/node` → `node` ≥ 24 в PATH) и пин TypeScript (`CLAUDE_HARNESS_TS` — экспортируется; сгнивший пин откатывается на тулчейн по `TOOLCHAIN.lock`); конфиг площадки чекаута; `NODE_COMPILE_CACHE`; снятие `NODE_OPTIONS` проекта; префильтр `pre-bash` по `bin/prefilter.regex` над копией команды без кавычек и `\` (промах у агента, `agent_id` в payload, — не выход, а запуск Node только для наблюдения friction: вердикт, падение и отсутствие рантайма до инструмента не доходят); код рантайма на pre-событиях перехватывается — не 0/2 значит `ask`/`deny` по режиму |
| `bin/run <script.ts \| --flag …>` | тот же пин Node, что у `bin/hook` (общий `bin/node-pin.sh`), для скриптов харнесса и его тестов: `harness/bin/run scripts/due.ts --all` из любого cwd (`~/.claude/harness/bin/run …` — через симлинк); путь как есть или относительно `harness/`; первый аргумент с «-» уходит node как есть; без Node ≥ 24 — rc 69, отката на `node` из PATH нет |
| `src/main.ts` | роутер `route()`: payload → гейты события (каждый в try/catch → `unknown(<имя>)`) → самый строгий вердикт → `emit()` |
| `src/emit.ts` | контракт выхода: `deny` rc 2 + stderr · `ask` JSON `permissionDecision` · `context` `additionalContext` (на stop и agent-stop — `systemMessage` человеку: additionalContext и block там дают модели новый ход, и его ответ подменяет итог или отчёт субагента) · Stop `decision: block` · `unknown` → на pre `ask`/`deny` по режиму, на остальных `context` |
| `src/config.ts` | конфиг площадки: `CLAUDE_HARNESS_CONFIG` → `~/.claude/harness.config.json` → `harness.config.json` в корне чекаута; нечитаемый файл — `problem`, и защищающие гейты закрываются (`pre-push-guard` — `unknown`, `owner-actions` — `deny`) |

| `src/sweep.ts` | сверка дерева на каждом пишущем событии: `git status -z -uall` по корням сессии, sha256, сдвиг HEAD, ярусы проверок, доставка находок по читателю: журнал корня `deliveries` и журнал каждого субагента `agent_deliveries`, субагенту — только файлы его окна (`src/window.ts`); доставка — один раз на содержимое: вернувшийся к сломанному виду файл сообщается снова |
| `src/checks/` | `syntax` (bash -n / node --check / py_compile / JSON), `project-check` (`.claude/check.sh <file>` проекта), `tsc-project` (воркер, TypeScript самого проекта и только он — `node_modules/typescript` до корня репозитория, а у проекта с `TOOLCHAIN.lock` рядом с `tsconfig.json` (сам харнесс, `harness/tsconfig.json`) — тулчейн этого замка с его `lib.*.d.ts` и `@types/node`; правка замка — `unknown`; fail ⟺ ошибок (файл, код, текст) больше, чем у HEAD — строки не считаются, переименования и тип, выросший в тексте сообщения, тоже; сторона HEAD — дерево и блобы коммита, с диска только то, что git игнорирует (окружение, не судится); база кешируется по коммиту и сверяется со stat прочитанных с диска файлов; правка зависимостей, сбой git или компилятора → `unknown`; tsconfig из одних references — объединение проектов, как `tsc -b`), структурные проверки, `contour-suite` (воркер: набор контура при правке `harness/**`, `hooks/**`, `settings.json`) |

## Выключатели

Каждый гейт и проверка гасятся своим `CLAUDE_SKIP_*=1` (читается роутером до любой записи). Список руками
не поддерживается — он печатается из реестра:

```sh
cd ~/.claude/harness && bin/run -e '
  await import("./src/gates/index.ts");
  const { GATES } = await import("./src/gates/registry.ts");
  const { CHECKERS } = await import("./src/checks/registry.ts");
  for (const g of [...GATES, ...CHECKERS]) console.log(g.name, g.killSwitch);'
```

Общего выключателя нет намеренно (I4): выключают один барьер, а не весь контур.

## Реестр предохранителей

Полный состав гейтов и сверки глазами модели: что останавливает, что требует шага, что ждёт окна, что пишет молча. CLAUDE.md держит только принцип и ссылку сюда; сообщение каждого deny/ask/block начинается с имени гейта (`src/emit.ts`).

Система строится так, чтобы **не зависеть от того, какая модель подключена**: haiku/sonnet/opus/fable/codex/mythos проходят одну планку, сильная быстрее, слабая дольше и дороже — но не хуже. Проверка любого элемента: *если качество зависит от того, насколько умна модель, элемент спроектирован неверно.* Спека — `specs/SPEC_FRICTION_LEDGER.md`; путь задачи от запроса до прода и что на каждом шаге держит машина, а что суждение корня — `specs/SESSION_E2E.md`.

**Каждый отчёт агента заканчивается секцией `## Трение`**: с чем столкнулся · как обошёл · что осталось в коде (тест/констрейнт/хук — или честное «ничего»). Для воркфлоу требование в промпте проверяет гейт; у Agent/Task — нет.

Отчёт и транскрипт агента харнесс **не читает** — это приватный текст. **Уровень** и **след** — свойства диффа: их считает `harness/src/friction.ts` на `SubagentStart`/`SubagentStop` и пишет в `~/.claude/exec-telemetry/personal-friction.jsonl` (`scope`, `trace_kind`, `safeguard_sufficient`, `attribution`); путей и содержимого в событии нет (тест). Агенту засчитывается только то, что записали его собственные вызовы (`adapter: claude-friction-3`, с 29.09): Write/Edit/NotebookEdit — по пути из post, Bash — по снимкам до и после его вызова, за вычетом файлов, которые в это время записали Write/Edit корня или другого агента. Корневая сессия в State не отслеживается: её Bash оставляет только метки `$state/root-bash/<сессия>.<tool_use_id>.{start,end,bg}` (`.start` пишет шим до префильтра, без fork; `.end`/`.bg` — post; протокол — `src/bash-calls.ts`). Bash-вызов агента с непустым диффом, чей интервал пересёк Bash корня своей сессии, называется `missing_reason: root_bash_overlap`, а событие получает `agent_overlapping`: уровень считается по всем файлам, авторство не засчитывается (узел `INC-FRICTION-SHARED-ROOT-FOREIGN-WRITES`). Журнал коммитов, который дописывает Stop корня, агенту не засчитывается никогда. Фоновый Bash агента — по `run_in_background` или `backgroundTaskId` в ответе — закрывается на его стопе; вызов без post (отказ гейта, прерывание) файлов не даёт и называется `missing_reason: call_unclosed`. `attribution: agent`, при другом открытом агенте в том же корне — `agent_overlapping` (узел `INC-FRICTION-AGENT-WINDOW-PARENT-EDITS`). Окно, открытое до выката, считается прежним диффом дерева (`claude-friction-2`). Агент без старта с типом (возобновлённый) — общее окно корня, `window`. Без старта и без типа — внутренний агент Claude Code: `internal`, уровня нет. Нарратив трения — `narrative_friction_state: unavailable`.

**Уровень считает скрипт по диффу, не модель** (функция / модуль / домен: миграция, схема, контракт, >1 репо); повысить его модель не может — входа для этого нет. **Решение качественное ⟺ в диффе остался детерминированный след** — формулировка отчёта на оценку не влияет. Миграция засчитывается следом только с констрейнтом/индексом, не «новая колонка».

**Повтор весомее первого появления.** Машина его не считает: повтор устанавливается сверкой с графом (`graph/incidents/`, тот же `root_cause`) на `/friction-review`. Домен и повторы идут владельцу контура, остальное копится молча; на доменной правке без следа харнесс молчит (`silent`), доставка владельцу — только через разбор. Предохранители по силе: констрейнт/индекс → property-тест/ассерт → хук → правило в скиле → строка здесь; **доменный уровень закрывается только констрейнтом или ассертом** — хук держит процессный риск, а не данные, схему или контракт (решение 22.09, так считает и `friction.ts`).

**Контур — планировщик, а не конвейер** (аналогия с БД): глубина проверки выбирается по `ущерб × P(ошибки)`; дешёвый детерминированный префильтр отсекает кандидатов до вызова модели; самая дешёвая проверка — та, которой не потребовалось (есть констрейнт — рассуждать не о чем); контекст не влезает — резать на срезы и сливать наверху.

**Реестр предохранителей** — харнесс v5 (слой v4 по ADR): все события `settings.json` идут в `harness/bin/hook` → `harness/src` (реестр — `src/gates/index.ts`); bash-хуки в `hooks/` заморожены и не подключены. Все молчат при штатном исходе; каждый гасится своим `CLAUDE_SKIP_*=1` из окружения процесса, не из команды — кроме `resource-guard`, который принимает разовый обход префиксом команды `CLAUDE_SKIP_RESOURCE_GUARD=1`. На pre-событиях «не разобрано» (`unknown`) в режимах `auto`, `bypassPermissions`, `dontAsk` — deny, в `default`, `acceptEdits`, `plan` — ask: проба 22.09 показала, что в bypass ask пропускает команду без вопроса. Человек возвращает ask на сессию `CLAUDE_HARNESS_UNKNOWN=ask`. Знать состав дешевле, чем узнавать о `deny` в момент отказа.

⛔ *Останавливают* — `model-gate` (явная модель у Agent/Task) · `workflow-friction-gate` (хотя бы один статический `agent()` не требует «Трение» ни в промпте, ни в `schema.properties.friction`) · `commit-msg-guard` (AI-атрибуция в сообщении коммита) · `pre-push-guard` (push и MR в защищённую ветку (`protectedBranches`) не с `release/*`|`hotfix/*`; H2 — `release/N+1` при незамкнутом прошлом релизе; исключения из правила обвязки — только списком владельца `harness/owner/pre-push-exceptions.json`) · `owner-actions` (разрешающий список к корпоративному GitLab: тег — создание, перенос, удаление, публикация любым refspec, `update-ref`, `glab release`, API `repository/tags`; чтение, diff и `git add` открыты) · `memory-frontmatter` (шапка ноты: frontmatter, `name` = имя файла, четыре типа; только путь `~/.claude/projects/*/memory/`) · `pg-session` (барьер к Postgres на состоянии соединения: GUC без `LOCAL`, роль/база-левел настройки, `options=-c`; SQL, спрятанный подстановкой, — deny) · `agent-revert` (субагент не уничтожает незакоммиченную правку отслеживаемого файла вне черновой зоны: checkout/restore (и `-p`)/reset --hard|--merge/clean -f/rm -f/switch -f/worktree remove -f, обратный патч, `git show >`/`| tee`/`| cat >`, cp/mv/install/ditto/rsync, `cat >`, `tee <` с содержимым, которое репозиторий уже хранит как объект (HEAD, другой коммит, индекс), rm и mv из репозитория, `rm -r`/`git clean -ff` над вложенными worktree — deny; любой stash, кроме list/show/create, — deny в любом дереве; Write/Edit с закоммиченным содержимым поверх правки — deny, если правка не своя (чист на старте и последняя запись этого агента); скобки и глобы раскрываются как в zsh, переменные путей — через `shellPaths`; недоказуемое — unknown, на этапе выката 1 (`agentRevert.unknown: note`) — заметка; вердикт доходит и из режима наблюдения шима (`observe`), унаследованный `HARNESS_OBSERVE` шим сбрасывает; корень не судится и не платит; ## Границы — что сверка не видит

Файлы под `.gitignore` (`.env`, `dist/`); деревья вне git (scratchpad); правки внутри контейнера/пода и в базе;
изменения после Stop до следующей сессии; деревья с числом изменённых файлов > 200 (сообщается `truncated`);
обфускация shell глубже одного уровня `sh -c`/`eval`, `base64 -d | sh`, команда из переменной — даёт `unknown`, не pass.
Команда, которую грамматика оболочки не дочитала, со словом любого pre-bash гейта в недочитанном хвосте — тоже
`unknown` (`shell-grammar`).
Here-doc в эти границы НЕ входит: тело `<<EOF` разбирается и судится (`git commit -F -`, `psql <<SQL`), а
`unknown` остаётся только там, где текст и правда неизвестен — подстановка в теле при голом ограничителе,
ограничитель без закрытия, here-string `<<<`, stdin из трубы.
Функция-обёртка `run() { psql … "$@"; }` с литеральными вызовами в той же оболочке — тоже не граница: pg-session
раскрывает её по каждому вызову и судит argv psql, который получится (плоское тело, безусловный `shift`, `"$@"`/`"$1"`
целым словом в кавычках). Условный `shift`, `set --`, `eval`, `"$*"`, `${@:2}`, вызов с подстановкой, из другой оболочки
или функция без вызова оставляют SQL скрытым — deny с причиной, чего не хватило.
Строка-команда обёртки — `docker exec … sh -c '…'`, `su -c '…'`, `ssh host '…'`, `watch '…'`, `find -exec sh -c '…'` —
разбирается как уровень +1, и stdin обёртки (here-doc, `<`, труба) доходит до команд её тела. Файл, который команда
пишет литеральным текстом (here-doc, echo, printf, tee — прямо или через трубу), проходит гейты записи так же, как
Write (`bash-writes`); содержимое, которого в команде нет — cp, sed -i, curl -o, скрипт, подстановка — не судится.
Закоммиченный сломанный файл сообщается один раз при сдвиге HEAD, дальше это забота тестов проекта.
`pre-push-guard` судит серию против локальных refs ремоута; при заданных `ownerHosts` серию MR читает с ремоута на корпоративном
хосте, а правило защищённой ветки держит push только в корпоративный или неразрешимый ремоут. Первый пуш в пустой репозиторий (refs нет и после fetch)
— `unknown`, в авторежиме deny; его делает владелец из своего терминала. Репозиторий, где обвязка и есть содержимое
(стенд), снимается с правила обвязки записью владельца в `owner/pre-push-exceptions.json`, а не обходом.
H1 сравнивает тела с деревом, которое останется: вершина ветки, которую push перезаписывает своим именем, таргетом не считается
(переименование `git mv` 048→051 проходит), а линия мержа — без файлов, удалённых веткой после ухода от неё (есть в merge-base, нет в HEAD).

## Известные дефекты

Критика 25.09 с репродьюсерами; исправлены «сломал → починил → снова сломал» и проход Stop при залоченном хранилище.
02.10 закрыты красным тестом каждый (перенесены на main 14.10): курсор `last_head` (на сессию, держится до вердикта
по закоммиченным файлам — `test/sweep/head-cursor.test.ts`), программа проекта на каждый файл задания (одна программа
рабочего дерева на проект в задании, база HEAD кешируется по коммиту, воркер докатывает задание —
`test/sweep/worker-batch.test.ts`), Stop, ждущий чужие задания (ждёт только задания по файлам текущего дерева), дубли
журнала коммитов после Stop, убитого между дозаписью и COMMIT, восстановление битой базы без `-wal`/`-shm`,
`git-freshness` на репозиторий вместо сессии, вечное окно агента без stop, fetch, заглохший после отката часов. Аудит
race-auditor того же дня добавил к курсору: он отпускается только после доставки корню (post субагента и бюджет отчёта
больше не теряют находку по закоммиченному файлу), закоммиченные пути не срезаются обрезкой первыми, неответивший
`git diff` держит курсор; восстановление битой базы не трогает уже созданную соседом новую (по inode), журнал коммитов
сверяется с файлом в каждой транзакции. Открыто:

- **низкий** — коммит в самом первом вызове, которым хоть одна сессия вошла в репозиторий (`repos.last_head` пуст),
  не диффится: курсору не от чего считать;
- **граница** — проверку закоммиченного файла sync-ярус откладывает, пока та же проверка на другом файле не уложилась
  в бюджет (правило 2×, чтобы один медленный `check.sh` не съедал дедлайн каждого события): курсор файл держит,
  `unknown` сказан один раз, вердикт придёт, когда медленный файл уйдёт;
- **средний** — телеметрия разбирает транскрипт внутри транзакции хранилища: лок дольше `busy_timeout` делает
  Stop `block` (не проход, но лишний ход модели). Вынос разбора из транзакции (попытка 02.10 в ветке
  `feature/compassionate-lamport-kbf3se`, откачена) ставил метку события позже чтения хвоста, и `telemetry-recount`
  засчитывал запись между ними как учтённую. Корень — отдельное хранилище телеметрии;
- **средний** — перемотка `git-freshness` (`git fetch . source/<b>:<b>`) видит воркtree только в момент записи:
  `checkout` этой ветки, который уже прочитал её и ещё распаковывает дерево, получит сдвинутую ветку под старым
  деревом (`git status` покажет изменения ремоута застейдженным откатом). Окно — длительность того checkout.
  Не-fast-forward, ветку под rebase/bisect и коммит в ветку между чтением и записью отбивает сам git.

Классы эквивалентности (`test/_equivalence.ts`, 32 обёртки × запрещённые действия `owner-actions`, `pre-push`,
`pg-session`, `data-boundary`): обёртка, не меняющая того, что исполнит оболочка, не меняет вердикт, и каждая форма
доходит до Node через шим. Первый прогон 02.10 нашёл и закрыл: ANSI-C `$'\x67it'` и имя команды из подстановок шим
отсекал до Node; `echo '…' | sh` и алиас из `git config` проходили `owner-actions`; имя, склеенное из переменных
(`a=ps; b=ql; $a$b`), и `setsid`/`stdbuf -oL` прятали команду от трёх гейтов. Граница: программа оболочки из
нелитерального stdin (`curl … | sh`) не судится, как скрипт-файл; алиас, заданный человеком вне агента, шим по
имени глагола не видит — агенту задать алиас с push/tag в корпоративном репозитории не даёт `owner-actions`, второй
барьер — защищённые ветки и теги GitLab.

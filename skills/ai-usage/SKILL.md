# /ai-usage — отчёт по AI-исполнителям

Два контура, считаются и отчитываются ОТДЕЛЬНО:
- **Внешние исполнители** — `codex`, `corp-claude`. Отдельные машины/логины, задача уходит наружу и возвращается отчётом.
- **Личные агенты** — `local-agent`: субагенты Agent-тула и workflow-агенты, работают внутри моей сессии.

Источники (глобальные, в `~/.claude/`):
- `ai-usage.md` — вердикты приёмки (✅/🟡/❌ + почему) и живые скоуборды обоих контуров.
- `exec-telemetry/corp.jsonl` и `exec-telemetry/personal.jsonl` — сырые события Stop-хука. **Три схемы по полю `adapter`**: до 05.09.2026 пишет `claude-telemetry/2` (`~/.claude/hooks/telemetry.py`), с 05.09 — `harness-telemetry-4` (`harness/src/telemetry.ts`), после фикса дедупа — `harness-telemetry-5` (тот же файл; граница расхода — ниже, в «Как читать токены»). Разделение контуров у python и TS РАЗНОЕ: старый клал Codex в `corp.jsonl`, TS относит Codex к ЛИЧНОМУ контуру (`telemetry.ts:8`). В `corp.jsonl` событий нет с 02.09 до 24.09 (простой корпа), с 24.09 корп пишет туда снова. Искать внешнего исполнителя только в `corp.jsonl` — значит объявить простой там, где его нет.

- Сырые события пишет Stop-гейт `telemetry` харнесса в `~/.claude/exec-telemetry/personal.jsonl` и `corp.jsonl`; kill-switch — `CLAUDE_SKIP_AI_USAGE=1`.
- `ai-usage-raw.jsonl` — тот же поток ДО 20.08.2026, заморожен. Для периодов до этой даты читать его, после — два файла выше. Событий из обоих источников на одну сессию не бывает.
- **Свёрнутые агрегаты.** События старше `TELEMETRY_RETAIN_DAYS` (30) заменяются суточными строками с `"aggregate": true` (поля `date`, `executor`, `sessions`, `total_tokens`, `output_tokens`). Их НЕ смешивать с сырыми при подсчёте сессий: агрегат уже несёт их число.
- `exec-telemetry/personal-friction.jsonl` — события `SubagentStop` (`harness/src/friction.ts`, `adapter: claude-friction-2`): `agent_type`, `attribution`, `scope`, `trace_kind`, `files_changed`. Джойнится к `local-agent` по `agent_id`. `attribution: internal` — внутренние агенты Claude Code (без старта и без типа): это не исполнители, из скоуборда их исключать. Секции «Трение» в журнале нет (`narrative_friction_state: unavailable`).
- Дополнительно по запросу: `find ~/.codex/sessions -name '*.jsonl'` → total_token_usage (точный расход Codex), `~/.claude-corp/tasks/done/REPORT_*.md` (объём и качество отчётов корпа).

### Как читать токены (иначе цифра врёт в разы)

- **Брать последнее событие на прогон, НЕ сумму событий.** Ключ прогона: `agent_id` у `claude-telemetry/2`, `session` у TS-схем. `harness-telemetry-4/5` `agent_id` не пишут, но зерно у `session` то же: для `local-agent` это sha256 пути транскрипта самого агента `…/subagents/agent-<agent_id>.jsonl` (`telemetry.ts`: источник — `sources()`, ключ — `sourceId(s.path, 'session')` в `collect()`), один ключ на транскрипт (21–24.09: 244 ключа = 244 транскрипта). Джойн к `personal-friction.jsonl`: `session == "session:" + sha256(путь agent-<agent_id>.jsonl)[:20]` (24.09: 229 из 229 agent_id с транскриптом). У `corp-claude` и Codex `session` — хеш пути файла сессии. Живой прогон переотправляется на каждом Stop (`claude-telemetry/2` метил такие события `"cumulative":true`, TS-схемы флага не пишут — семантика та же). Июль: 204 события против 49 сессий, сумма завышала расход в 4,4 раза.
- **Граница расхода Claude-транскриптов — `adapter` каждого события; первое `harness-telemetry-5` — фикс 24.09.2026.** У `local-agent` и `corp-claude` события `harness-telemetry-4` и `claude-telemetry/2` (с 20.08) несут сумму по СТРОКАМ транскрипта, а Claude Code пишет ответ модели строкой на content block с одним `message.id` и повторённым usage: ввод без кэша завышен примерно вдвое, output — от ×1,05 до ×2 (21–24.09: личные ×2,05 и ×1,05, корп ×2,21 и ×2,06); `ai-usage-raw.jsonl` до 20.08 не проверен. Сравнивать расход через границу нельзя. Старый период — только пересчётом: `~/.claude/harness/bin/run scripts/telemetry-recount.ts --since <ISO> [--until <ISO>] [--journal]` (то же правило, что у гейта; окно — по последней записи транскрипта; по исполнителю — транскрипты, ответы, строки без `message.id`, ввод без кэша, output); журналы не переписываются. С `--journal` скрипт сверяет последнее событие каждой `session`: расхождение у `-5` — находка и код 1 (триггер отката фикса), у `-4` и `claude-telemetry/2` — коэффициент завышения; код 2 — пусто, частично или нечего сверять. 21–24.09 он дал 41,94M ввода без кэша у личных агентов и ×2,051 у `-4`. Событие `-5` равно такому пересчёту своего файла: ответ опознаётся по `message.id`, без него — по `requestId`, затем по `uuid` строки; реплей истории и копия ответа с нулевым usage считаются один раз. Если харнесс откатят на старый код, событие `-4` той `session`, где уже было `-5`, — гибрид (точный префикс и построчный хвост): брать последнее `-5` или пересчёт. У Codex `-4` и `-5` одинаковы — `total_token_usage` точен и до границы.
- **Не сравнивать исполнителей по `total_tokens`.** У всех 95-97% объёма — чтение кэша, оно на порядок дешевле. Сравнивать по `output_tokens` и вводу без кэша. **Имя поля кэша зависит от схемы:** `claude-telemetry/2` пишет `cache_creation_input_tokens`/`cache_read_input_tokens`, `harness-telemetry-4/5` — `cache_write`/`cache_read`, и `total_tokens` не пишут вовсе. Ввод без кэша: Codex `input - (cached_input_tokens либо cache_read)`; корп и личные `input + (cache_creation_input_tokens либо cache_write)`. Считать по одному имени — занизить: на окне 07-09.09 формула со старым именем дала 6,9k вместо 11,4M.
- **`last_turn_tokens` — исторический ключ** (события до 10.08): расход одного хода, не итог сессии. В расчёт периода не брать; июль закрыт бэкфиллом с `"backfill":true`.

## Шаги

1. **Период**: из аргументов; иначе текущая неделя. Преобразовать в [from, to].
2. **Собрать**: вердикты из `ai-usage.md` за период + события из `exec-telemetry/*.jsonl` (плюс `ai-usage-raw.jsonl` для дат до 20.08), фильтр по ts; расход `local-agent` и `corp-claude` для окна до первого `harness-telemetry-5` — из `scripts/telemetry-recount.ts`, не из журнала. Сверить: событие без вердикта = «принято без оценки» — перечислить отдельно (дыры приёмки).
3. **Отчёт — двумя раздельными блоками**, не сваливать в одну таблицу:
   - **Внешние исполнители** (Codex, корп): задач · ✅/🟡/❌ · характерные успехи/провалы (1 фраза) · расход (прогоны, ввод без кэша, output). Здесь вердикт ожидается на каждую задачу — простой исполнителя тоже находка.
   - **Личные агенты** (`local-agent`): прогонов (считать по уникальным парам `session`+`agent_id`: у агента бывает несколько стопов, `window` — повторный) · разбивка по `agent_type` из `personal-friction.jsonl` · сколько из них workflow-агентов · расход · разбивка по `outcome`/`verification_state` (доля прогонов с секцией «Трение» по телеметрии недоступна — не подставлять вместо неё другую цифру). Вердиктов здесь по одному на прогон НЕ ждать — оценивается пачка (воркфлоу, волна субагентов), а не каждый агент; дыра приёмки считается по пачкам без вердикта, не по прогонам.
   - **Рекомендации раздачи**: подтвердить/скорректировать колонку «Правило раздачи» в обоих скоубордах по свежим фактам. Изменилось → обновить `ai-usage.md` (скоуборды живые, дубли не плодить).
   - **Дыры**: пачки без вердикта, исполнители без задач (простаивающий ресурс — например Codex), прогоны с `agent_type: unknown` (нечем атрибутировать).
4. Кратко, таблицами. Без пересказа задач — только пригодность исполнителей.

## Правило ведения (для оркестратора, вне этого скилла)
При приёмке результата — одна строка в `ai-usage.md` под текущий месяц (`echo >> `, бесплатно), в свой раздел: внешние исполнители — построчно на задачу; личные агенты — на ПАЧКУ (воркфлоу целиком, волна субагентов, чип-сессия), а не на каждый прогон. Вердикт честный: ❌ с уроком ценнее ✅. Скоуборды рефакторить при смене картины, не плодить строки.

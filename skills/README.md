# Скиллы по слоям — куда идти и зачем

Имя начинается со слоя. Не нашёл слоя в имени — значит это сквозная дисциплина, а не слой. Новый скилл —
`brain new skill <имя>`; строка добавится в раздел «Свои».

## Слой UI/UX

| Скилл | Идти сюда, когда |
|---|---|
| `ui-design` | проектируешь экран **до** вёрстки: размер, шкала, контраст, состояния, плотность под мобильный/десктоп |
| `ui-render-review` | вёрстка есть, но моргает: прыжки заливок, FOUC, layout-shift, артефакты перехода |
| `ui-flow-qa` | экран готов: пройти флоу как пользователь и поймать баги фронта и бэка за один проход |
| `ui-onboarding` | объясняешь пользователю, как работать в системе: видеоинструкция или тур по экранам |
| `ui-flow-map` | рисуешь карту движения данных: дашборд очередей, сцена потока — что кодирует каждый канал и чем доказано, что сцена не врёт |

Порядок ровно такой. Дизайн-решение, принятое после вёрстки, чинится в десятках мест сразу.

## Слой код

| Скилл | Идти сюда, когда |
|---|---|
| `code-spec-and-verify` | начинаешь нетривиальное изменение — зафиксировать контракт и инварианты ДО кода, и проверить адверсариально ПОСЛЕ |
| `code-tests` | пишешь или правишь тест: как доказать инвариант, а не сопроводить правку |
| `code-delivery-audit` | дифф трогает события, очереди, вебхуки, outbox, after-commit — всё, где запись в БД обязана превратиться в доставку |
| `code-config-driven` | поведение задаётся данными, а не кодом: опции стадий, типы операций, правила в БД |

## Сквозные: дисциплина доказательства

| Скилл | Идти сюда, когда |
|---|---|
| `measurement-chain` | перед выводом о производительности: не упёрлись ли в сам замерятель |
| `metrics-verify` | до реализации метрики и при её приёмке: сходится ли с фактом в БД, что на пустых данных |
| `info-archaeology` | «кто писал», «есть ли такое», «в какой ветке» — когда рабочее дерево может врать |
| `verification-report` | результат прогона уходит людям вне команды |

## Знание и документы

| Скилл | Идти сюда, когда |
|---|---|
| `project-documentation` | создаёшь или чистишь любой документ проекта; описание задачи для трекера |
| `knowledge-graph` | сводишь разрозненные находки в карту системы |
| `change-notes` | результат сессии или состав релиза уходит бизнесу и пользователям — по фактам из git (`harness/scripts/change-facts.ts`) |

## Контур и журналы

| Скилл | Идти сюда, когда |
|---|---|
| `friction-review` | разобрать накопленное трение агентов, решить, где нужен предохранитель |
| `memory-review` | ревизия memory-нот: протухшие статусы, дубли, сироты |
| `ai-usage` | кто из исполнителей с чем справился, куда раздавать задачи |
| `worklog` | отчёт за период из журнала работ |

Расписание, которое напоминает про `friction-review` / `memory-review` / `ai-usage` / `worklog` по накоплению
данных, — `specs/schedule.json` + `harness/scripts/due.ts`.

Доменные скиллы площадки живут в пресетах: `presets/postgres-k8s/skills/` — `data-boundaries`, `db-performance`,
`local-stand-findings`.

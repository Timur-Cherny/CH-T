# Заметки об изменениях

Отвечает на один вопрос: **что изменилось для тех, кто системой пользуется и за неё платит.** Не «что мы делали» (это `worklog`) и не «как проверяли» (`verification-report`).

Правило нулевое: **каждое предложение заметок указывает на факт** — коммит, текст интерфейса, маршрут API, миграцию, имя теста. Предложение без факта уходит в раздел «не подтверждено» или не уходит никуда. Факты собирает скрипт, текст пишет модель; поменять их местами нельзя.

## Два входа, один артефакт

| вход | диапазоны | откуда берутся |
|---|---|---|
| **сессия** | коммиты сессии из журнала, сцепленные по первым родителям, — по каждому репозиторию | `--session "$CLAUDE_CODE_SESSION_ID"`; чего журнал не видит, сессия добавляет тройками, скрипт проверяет их по git |
| **релиз** | по каждому репозиторию релиза: `<прошлый тег>..<тег релиза>` | теги с `source`, после `git fetch source --tags` |

Для входа «сессия» диапазоны даёт журнал `worklog-commits.jsonl`. Stop-хук пишет туда коммиты из всех корней сессии, а не только из репозитория, где она открыта (спека `specs/SPEC_COMMITS_ALL_ROOTS.md`). Скрипт относит каждый коммит к одному виду, и в заметках вид виден:

| вид | что доказано | как писать |
|---|---|---|
| `session` | HEAD сдвинул git-глагол этой сессии (`commit`, `merge`, `rebase`…), выполненный в том воркtree, и никакая другая сессия не могла сделать это в тот момент | как сделанное |
| `shared` | сессия в `candidates`: в тот момент в воркtree работала ещё сессия, либо её вызов мог сделать коммит, но не доказал этого (обёртка `bash -lc`, скрипт, `cd "$VAR"`) | с оговоркой «одна из сессий» |
| `legacy` | строка записана до атрибуции — первой увидевшей сессией | с оговоркой |
| `pending` | коммит сделан в воркtree, где работала сессия, моложе 11 минут — атрибуция ещё не устоялась | с оговоркой; через 11 минут прогнать снова |

Коммит, для которого улики нет вообще (`window` без `candidates`), в диапазоны сессии не входит — это не её доказанная работа. Не видит журнал и репозиторий, куда сессия заходила только через `cd "$VAR"`, если переменной нет в окружении хука. Такие диапазоны сессия называет тройками сама.

В сессии есть результат и **вне git**: диагноз, решение владельца, открытый MR, заведённая задача, запись в памяти. Он перечисляется отдельным блоком «Не из git» и не выдаётся за изменение продукта.

## Порядок

1. **Собрать факты** (0 токенов, только чтение git):
   ```bash
   set -a; . ~/.claude/env/harness.env; set +a
   "$CLAUDE_HARNESS_NODE" --no-warnings ~/.claude/harness/scripts/change-facts.ts \
     --repo <mobile-repo> --from v4.2.3 --to v4.3.0 \
     --repo <backend-repo> --from v1.49.0 --to v1.50.0 \
     --memory <memory-dir>
   ```
   Тройка `--repo --from --to` повторяется на каждый репозиторий. Для итога сессии вместо троек — `--session "$CLAUDE_CODE_SESSION_ID"`, тройки можно добавить к нему. Вид каждого коммита лежит в `session.commits`. Коды: `0` факты · `1` диапазон пуст или у сессии нет своих коммитов · `2` ссылка не разрешается · `64` неполная тройка. **Код 1 — это перепутанные ссылки или не та сессия, а не «изменений нет»**: чинится вход, а не текст.
2. **Прочитать названные ноты памяти.** Скрипт отдаёт только имя и описание нот, упоминающих коммит, тег или ветку диапазона. В них лежит то, чего нет в git: что должен включить администратор, кому доступно, что решено не делать, что не прогонялось.
3. **Установить статус выката** — словарём ниже, фактом, не памятью.
4. **Написать заметки** по контракту вывода.
5. **Пройти приёмку.**

## Что значит каждый факт

| факт скрипта | что это для читателя |
|---|---|
| `texts` added | новая кнопка, подпись или сообщение. Русский текст цитируется ДОСЛОВНО — оператор увидит именно его |
| `texts` changed | то же место выглядит иначе: «было → стало» |
| `texts` removed | элемент интерфейса убран |
| `routes` added / removed | у системы появилась или пропала возможность; для интеграторов — контракт |
| `migrations` | меняется состав настроек или данных. `down: empty` или `absent` — откат данные не вернёт, это говорится вслух |
| `tests` | в этой кодовой базе имя теста — утверждение о поведении. Пересказывать по-русски и по-человечески, английский заголовок в заметки не вставлять |
| `removedFiles` | удалённый экран или модуль — кандидат в «Убрано» |
| `layers` | где лежит изменение: `ui` и `texts` видит пользователь, `api` и `contract` — интеграторы, `migration` — администратор |
| `diverged.behind` | основная ветка ушла вперёд на N коммитов: работа ещё не поверх актуального кода |
| `containment` | где живёт конец диапазона: теги и основные ветки, которые его содержат |
| `memory` | какие ноты читать |

## Статус выката — словарь

Одно изменение — один статус, самый сильный из доказанных.

| статус | чем доказывается |
|---|---|
| **на проде** | образ пода или версия APK на устройствах. В git этого нет — проверяется на самом контуре |
| **в релизе vX** | `containment.tags` содержит тег |
| **в main** / **в dev (обкатка)** | `containment.branches` |
| **MR открыт** | `glab mr view` |
| **только локально** | ветка не запушена |

Раздел «После выката» строится **только** из статусов «в релизе» и «на проде». Если прод не проверялся — так и пишется: «в релизе 4.3.0; на устройствах не проверено». Влито и работает — разные утверждения: бэкенд может крутиться на проде, не входя в `main`, а влитый мобильный клиент доезжает до устройств только установкой APK.

## Контракт вывода

Один документ, три части.

**А. Бизнесу** — до 250 слов. «Добавлено · Изменено · Убрано · Исправлено», сгруппировано по тому, кого касается: мобильный клиент · офис (веб) · интеграции · администрирование. Язык результата, а не механизма: «оператор привязывает короб сканом, не уходя с экрана», а не «добавлен `carrierScanBeforeGoods`». Затем: **что нужно включить и кому** · **статус выката** · **известные ограничения и чем они закрыты** · **что НЕ вошло**.

**Б. Пользователям** — по ролям (оператор, менеджер, администратор). Что теперь на экране (точные тексты), что делать иначе, что перестало работать. Без имён веток, файлов и задач.

**В. Проверка утверждений** — таблица «утверждение → факт» (sha коммита, ключ текста, маршрут, имя теста). Наружу может не уходить, в рабочей версии обязана быть: по ней заметки проверяет следующий читатель, не поверив на слово.

## Правила, каждое из реального случая

- **Убранное и изменённое весят столько же, сколько добавленное.** Новый отказ там, где раньше принималось, — это «Изменено», с цитатой нового сообщения. Молчание про убранное ломает работу пользователей утром после выката.
- **Возможность за опцией или ролью не «доступна», пока её не включили.** Пишется, кто включает и где. Быстрая отгрузка (4.3.0) видна только ролям менеджера и администратора и только на стадиях, где администратор включил `fastDispatch`.
- **Ветку сравнивают с точкой ответвления, а не с текущим концом основной.** Скрипт делает это сам. Дифф двух концов руками показал «убран маршрут `POST /admin/orders/dispatch`» по ветке из одного коммита: основная ветка получила быструю отгрузку уже после ответвления. В заметках это звучало бы как «мы удалили выпущенную функцию».
- **Не-цели называются.** Что сознательно не вошло и почему — отдельной строкой, иначе читатель ждёт этого в выкате.
- **Непрогнанное называется непрогнанным.** «На устройстве не проверялось» — законная строка, её отсутствие — нет.
- **Никаких строк бизнес-таблиц, персональных данных и секретов.** Примеры — синтетические (`data-boundaries`).
- **Заметки — снимок.** В шапке: дата, репозитории, диапазоны, sha концов.

## Приёмка

- [ ] факты собраны скриптом, код возврата 0 по каждому диапазону;
- [ ] у каждого предложения частей А и Б есть строка в части В;
- [ ] «Убрано» и «Изменено» заполнены или явно пусты («ничего не убрано»);
- [ ] у каждой возможности за опцией или ролью сказано, кто её включает;
- [ ] статус выката установлен словарём; «на проде» — только с проверкой образа или APK;
- [ ] названы не-цели и непрогнанное;
- [ ] в частях А и Б нет имён веток, файлов, функций и английских заголовков тестов;
- [ ] результат вне git вынесен в «Не из git».

## Смежное

`worklog` — отчёт за период. `verification-report` — отчёт о прогоне. `/product-management:stakeholder-update` — статус руководству. Конвенция MR проекта — раздел «What ships» релизного MR; его удобно писать из тех же фактов. Что реально крутится на контуре, устанавливается проверкой самого контура, а не git. `info-archaeology` — когда диапазон приходится искать в истории.

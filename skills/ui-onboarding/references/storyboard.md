# Формат сценария

Один JSON на ролик. Пути к кадрам — относительно файла сценария. Координаты — в пикселях исходного кадра (например, 720×1600 для скриншота телефона), а не холста.

```json
{
  "title": "Мобильный клиент: брак в зону аномалий",
  "device": "phone",              // "phone" — кадр в корпусе телефона; "web" — в окне браузера
  "frame": [720, 1600],           // размер всех кадров, px
  "pace": 1,                      // множитель времени; >1 медленнее (для новичков), <1 не ставить
  "brand": "img/logo.png",        // необязательно: логотип в углу
  "intro": { "kicker": "Зона аномалий", "title": "Брак и непродажный товар", "lead": "Что делать, если товар нельзя продавать." },
  "chapters": [
    { "id": "defect", "title": "Брак / непродажный", "lead": "Уберите товар из продажи в зону аномалий." }
  ],
  "steps": [
    {
      "id": "scan-cell",
      "chapter": "defect",
      "frame": "img/n11-defect-product.png",       // что на экране, пока читают подпись
      "target": [34, 1422, 652, 128],              // x, y, w, h цели на кадре
      "zoom": "auto",                              // true / false / "auto" (по размеру цели)
      "kicker": "Брак",                            // необязательно: короткая метка над заголовком плашки
      "caption": { "title": "Сканируйте ячейку, откуда берёте", "body": "Из этой ячейки товар спишется в зону аномалий." },
      "claim": true,                               // фраза о поведении системы
      "evidence": "стенд 06.10, ANM-000038: остаток B-01-01 95 → 94",
      "action": { "type": "scan", "at": [360, 1486], "value": "B-01-01" },
      "result": "img/n12-defect-cell.png",          // кадр после действия
      "hold": 1,                                   // множитель времени чтения этого шага, ≥ 1
      "side": "left",                              // необязательно: где ставить плашку (left/right/above/below), если авто мешает
      "pad": 6                                     // необязательно: отступ рамки от цели, px холста, 0–24 (по умолчанию 6); рамка задевает соседнюю строку — меньше
    }
  ],
  "summary": { "title": "Брак — запомнить", "items": ["Товар → ячейка → вид и причина", "Последний скан — ячейка зоны аномалий"] }
}
```

## Действия

| `type` | что видно | обязательные поля |
|---|---|---|
| `tap` | палец подъезжает к точке и касается (телефон) | `at` внутри `target` |
| `click` | курсор подъезжает и кликает (веб) | `at` внутри `target` |
| `scan` | бейдж «Скан: КОД» на поле | `value`, `at` — центр поля, внутри `target` |
| `type` | набор текста на поле | `value`, `at` — центр поля, внутри `target` |
| `none` или нет `action` | только объяснение | — |

Бейдж скана и набора стоит центром в точке `at`, то есть на самом поле: над полем он закрыл бы подпись, под полем — соседнюю кнопку. Линтер требует `at` внутри `target`.

Коды вида ANM-000038, B-01-01, 992101–992103 плеер сам не переносит по дефису: оборачивать их в `nowrap` не нужно.

Шаг-карточка без кадра — схема, правило, что происходит за кадром: `{ "chapter": "cases", "claim": true, "evidence": "...", "card": { "kicker": "Случай 4", "title": "Отказ при подборе", "lead": "...", "items": ["..."] } }`. Пункты появляются по одному. Карточка почти всегда говорит о поведении системы, поэтому `claim` у неё обязателен: `true` с `evidence` или явное `false`.

## Как резать на шаги

- Одно нажатие, скан или ввод — один шаг. Объяснение, что видно на экране, — отдельный шаг без действия (`"Проверьте «Свободно»"`).
- Подпись описывает текущий кадр. Действие ведёт к кадру `result`. Следующий шаг начинается с этого кадра.
- Глава — одна задача целиком, 6–12 шагов. Больше — дели на две.
- Нестандартный случай («товара нет в ячейке») — отдельная короткая глава. Подписи берутся из того, что система реально делает, с `evidence`.

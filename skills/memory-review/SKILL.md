# /memory-review — ревизия memory-нот

Память растёт без чистки: статусы «НЕ запушено» переживают пуш, дубли перекрываются,
сироты выпадают из индекса. Ритуал: **префильтр (0 токенов) → читать только
кандидатов → вердикт по каждому → правки Edit'ом → короткая сводка в чат**.
Запуск — вручную, раз в неделю (человек-гейт: ревизия меняет память намеренно).

## Шаги

### 1. Префильтр (детерминированный, до любого чтения нот)

```bash
. ~/.claude/env/harness.env
"$CLAUDE_HARNESS_NODE" --disable-warning=ExperimentalWarning ~/.claude/harness/scripts/memory-prefilter.ts \
  <memory-dir> <рабочее-репо> ... <репо-харнесса>
```

- `<memory-dir>` — папка памяти текущего проекта (из системного промпта).
- Дальше — рабочие репо, на чьи коммиты ссылаются ноты; передавать те, что есть локально. Репо харнесса
  тоже. Живые линии — `protectedBranches` и `integrationBranches` конфига площадки; у репозитория без них
  живой линией считается ветка, на которую смотрит HEAD его remote. Перед прогоном — свежий `git fetch` в каждом: containment считается по remote-веткам.
- Нужен Node ≥ 24 (в обычной оболочке `node` может быть старше — поэтому пин из `harness.env`).
- Выход TSV: `FLAG → файл → доказательство`. Флаги:
  - `STALE` — маркер незавершённости («не влит», «не смёржены», «черновик», «не заводить», «в `main` нет»,
    «открыт !N», «ждёт слова»… в теле ноты ИЛИ только в её строке `MEMORY.md`), и **рядом с маркером** (±2 строки
    абзаца) назван коммит, который уже лежит в живой линии. В доказательстве — сама строка с маркером, коммит,
    линия и первый релизный тег: git-факт добыт, перепроверять не надо. Запись `756d4f79≈c1ee0b96→…` — **близнец**:
    сам хеш в линию не входит, но тот же патч лежит там под другим хешем (черри-пик dev → release; находит
    `git cherry`, предковость его не видит). Для статуса «влит/не влит» близнец равен самому коммиту;
  - `MAYBE` — тот же маркер, но приземлившийся коммит назван в другом месте ноты (база ветки, вершина main как
    ориентир). Решать по строке в кавычках: открывать ноту, только если маркер про слияние именно этой работы;
  - `ASKPROD` — нота говорит «на проде нет», а коммит уже в релизном теге. Что выкачено, git не знает —
    это вопрос владельцу, не правка;
  - `ORPHAN` (нота без строки индекса или строка индекса без ноты), `AGE60` (>60 дней без правки),
    `HOT` (≥3 упоминаний в worklog), `DUP` (≥4 общих слов, редких для корпуса, в имени и описании);
  - `INFO` — знаменатели прогона: сколько нот несут маркер, сколько хешей известны репозиториям, какие
    живые линии найдены. **Ноль по `STALE` ничего не значит, пока `INFO` не покажет, что смотрели**:
    «репозиториев 0» или «известны репозиториям 0» — прогон не состоялся, а не «память чиста».

### 2. Читать ТОЛЬКО отфлаженные файлы (обычно 10-25 из ~120)

### 3. Вердикт по каждому кандидату

- **STALE** → снять/обновить маркер статуса (факт «в какой линии и теге» уже в evidence;
  переформулировать 1-2 строки, не перечитывать git). Историю не стирать, а датировать — и без слов-маркеров:
  «на 16.09 MR ждал ревью», а не «был черновиком», иначе нота будет флажиться каждую неделю.
- **MAYBE** → по строке в кавычках: опорный коммит — скип без чтения ноты; маркер про ту же работу
  (черри-пик под другим хешем, сквош) — читать и править как STALE.
- **ASKPROD** → ноту не переписывать по git; вынести вопрос в сводку с тегом из evidence. Править можно, только
  если сама память фиксирует выкат (нота о релизе с датой) — тогда сослаться на неё.
- **ORPHAN** → мусор/черновик — удалить; ценная — добавить строку в MEMORY.md.
- **DUP** → слить в одну ноту (свежая как база), старую удалить, поправить
  [[ссылки]] и MEMORY.md. Ложный дубль (пересечение слов ≠ пересечение смысла) — скип.
- **HOT** → суть (1-2 строки) вынести в CLAUDE.md соответствующего уровня;
  ноту сжать до деталей или удалить.
- **AGE60** → быстрая проверка актуальности: устарела → удалить/обновить;
  живая — не трогать (сам по себе возраст — не приговор).

### 4. Применить и отчитаться

- Правки — Edit нот + MEMORY.md напрямую. Никаких report-файлов.
- В чат — короткая сводка: снято статусов N, слито M, удалено K, промоутнуто P.
- Удалённые ноты перечислить поимённо (юзер может вернуть из git vault'а).

## Уроки боевых прогонов

- Индекс-строки MEMORY.md дрейфуют между сессиями — правки индекса применять **по якорю
  `(имя-файла.md)`** (замена всей строки), не по цитате старого текста.
- Агентам-вердиктам требовать old-строки как ТОЧНЫЕ копии из файла (не пересказ) и полные
  пути файлов; проверять применимость `count==1` перед заменой.
- Прежде чем писать «влито» — раздельный статус по КАЖДОМУ репо/коммиту ноты (движок мог
  уехать в прод, а коннектор-фиксы того же дня — нет).
- 20.09: bash-префильтр отдал «0 STALE» при семи опровергнутых нотах — словарь маркеров не совпадал с языком
  нот, семизначные хеши пропускались, индекс не читался. Его заменил `harness/scripts/memory-prefilter.ts`
  (тест `harness/test/scripts/memory-prefilter.test.ts`); новые формулировки статуса добавлять в `MERGE` там же
  и сразу кейсом в таблицу `mergeMarker` теста. Пустой результат детектора сверять со строкой `INFO`.
- 20.09, пятая причина: проверка по SHA не видит близнецов. `adopted-box-phantom-mint` числилась «фикс только в dev»,
  хотя весь откат лежал в main с v1.47.0 под другими хешами, а `d8ea3031` и вовсе отменял то, что нота называла
  фиксом. Прежде чем писать «только в dev» — `git cherry <живая линия> <хеш> <хеш>^` (минус = патч уже там), а для
  реверта — читать сам дифф: «влит» и «действует» не одно и то же.
- Тег в релизной ветке ≠ влит в main (v1.50.0 стоял на `release/1.50.0` до мержа): «влит» писать по линии из
  evidence, а не по наличию тега.

## Ограничения

- Не трогать ноты без флага. Не выдумывать вердикт без чтения ноты.
- Сомнение (нота выглядит живой, но флаг стоит) → оставить + спросить юзера в сводке.
- Confidence-скоринг/decay не вводить — статус ноты бинарный, git решает споры.

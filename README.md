# CH-T — базовый слой харнесса для ИИ-исполнителей

Детерминированный слой проверок и один запуск для разных исполнителей: **Claude Code, Codex, Antigravity и
локальная модель** работают под одними гейтами. TypeScript под Node 24, без сборки и без `node_modules`.

## Зачем

Планка качества держится машинерией и не зависит от того, какая модель подключена: сильная проходит её быстрее,
слабая — дольше и дороже, но не хуже. Проверка любого элемента контура: *если качество зависит от того, насколько
умна модель, элемент спроектирован неверно.* Отсюда:

- **проверка висит на состоянии рабочего дерева, а не на событии инструмента** — правка любой дверью (`Write`, `sed`,
  heredoc, `python -c`, `git apply`, MCP, субагент) видна одинаково;
- **вердикт выносят парсеры, а не regex** — SQL разбирает libpg_query, TypeScript — compiler API проекта, команду
  оболочки — собственный парсер по грамматике POSIX с расширениями bash;
- **отсутствие данных — это `unknown`, а не тишина и не `pass`**; там, где человек не увидит вопроса, `unknown` — отказ;
- **один язык, один процесс на событие, один контракт выхода** — и один реестр гейтов для всех исполнителей.

## Слои

| Слой | Где | Что |
|---|---|---|
| Ядро | `harness/` | гейты (`src/gates`), проверки изменённых файлов (`src/checks`), парсеры, сверка дерева, состояние в `node:sqlite` — [`harness/README.md`](harness/README.md) |
| Дополнения | `harness/addons/` | гейты, которые нужны не каждой площадке: `data-boundary` — прод-данные и секреты на выходе ([README](harness/addons/data-boundary/README.md)); включено по умолчанию, `dataBoundary.enabled: false` выключает |
| Исполнители | `bin/brain`, `runtimes/` | запуск Claude / Codex / Antigravity / локальной модели в checkout, общие хуки, передача заметки между ними |
| Дисциплина | `skills/`, `agents/` | скиллы доказательства (спека → проверка, тесты, метрики, доставка, UI) и субагенты `spec-critic`, `race-auditor` |
| Генераторы | `scaffold/` | `brain new skill\|gate\|checker\|agent\|runtime\|spec\|preset` — [`scaffold/README.md`](scaffold/README.md) |
| Пресеты | `presets/` | то, что принадлежит площадке: каналы MCP, скиллы домена, фрагменты конфига — `postgres-k8s` |

## Установка (macOS и Linux)

```sh
git clone https://github.com/Timur-Cherny/CH-T ~/src/ch-t && cd ~/src/ch-t

# 1. Node 24 для контура, симлинк ~/.claude/harness, прогрев compile cache.
#    Нет Node >= 24 — --ensure-node скачает официальную сборку в ~/.claude/env/node со сверкой SHASUMS256.
harness/install.sh --ensure-node
# 2. TypeScript для проверок содержимого — ровно по harness/TOOLCHAIN.lock.
~/.claude/harness/bin/run scripts/toolchain.ts --install
# 3. События Claude Code. Своего ~/.claude/settings.json нет — симлинк; есть — перенеси в него блок "hooks".
ln -s "$PWD/settings.json" ~/.claude/settings.json
# 4. Скиллы и агенты.
for s in skills/*/; do ln -s "$PWD/$s" ~/.claude/skills/; done; for a in agents/*.md; do ln -s "$PWD/$a" ~/.claude/agents/; done
# 5. Исполнители кроме Claude: команда brain и общие хуки — Codex по умолчанию, Antigravity явно.
bin/brain install --runtime codex --runtime agy && brain doctor
# 6. Необязательно: конфиг площадки и машины (оба вне git).
cp harness/harness.config.example.json ~/.claude/harness.config.json
cp brain.config.example.json brain.config.json
```

Проверить ядро: живой ответ барьера (явная модель у субагента запрещена — ждём rc 2 от `model-gate`) и сьют.

```sh
printf '{"session_id":"check","cwd":"%s","hook_event_name":"PreToolUse","permission_mode":"default","tool_name":"Agent","tool_input":{"model":"haiku"}}' "$PWD" \
  | ~/.claude/harness/bin/hook pre-agent; echo "rc=$?"
cd harness && ~/.claude/harness/bin/run --test 'test/**/*.test.ts' 'addons/**/*.test.ts'
```

## brain — один харнесс, разные исполнители

```sh
brain claude --task returns                          # Claude Code в текущем checkout с контекстом задачи
brain codex  --task returns --model gpt-5.5 --effort high
brain agy    --task returns                          # Antigravity CLI; контекст приходит хуком SessionStart
brain local  --task returns                          # локальная модель: агент в браузере (ниже)
brain checkpoint --task returns --file note.md       # заметка следующему исполнителю
brain context --task returns                         # что он получит
brain new list                                       # генераторы
```

Переключение — новая сессия с явной заметкой: транскрипт и скрытое состояние другой модели не переносятся. Checkout
блокируется на время работы исполнителя; отпечаток (HEAD + дифф + неотслеживаемые файлы) говорит следующему, менялось
ли дерево после заметки. Исполнитель получает окружение без учёток запускающей оболочки (токены, пароли, ключи), кроме
входа самого клиента и `envKeep` из `brain.config.json`.

| Исполнитель | Как подключены гейты | Чего нет |
|---|---|---|
| Claude Code | `settings.json` → `harness/bin/hook` — все события | — |
| Codex | `~/.codex/hooks.json` + профиль `brain` → `runtimes/codex.ts`; `ask` → `deny` (Codex выполняет инструмент, на который хук ответил ask); патч — только разобранной формой `apply_patch <<'EOF'` | MCP вне `mcpAllowed`, субагенты, `-c/--config/--enable/--disable` при запуске; хуки требуют review/trust в `/hooks` |
| Antigravity | `~/.gemini/config/hooks.json`, запись `ch-t-harness` → `runtimes/antigravity.ts`; находки сверки — в следующий ход модели через `PreInvocation`; Stop держит агента `decision: continue` | субагенты, `schedule`, ввод в живой терминал (`manage_task` кроме просмотра), постоянный терминал (`RunPersistent`, `RequestedTerminalID`), неизвестные инструменты |
| Локальная модель | агентный цикл `runtimes/local/agent.ts` сам зовёт реестр до и после каждого вызова | — (инструменты свои: bash, чтение/запись/правка файлов внутри репозитория) |

Каждый реестровый гейт либо достигается событием исполнителя, либо назван в его таблице N/A с причиной — тесты
адаптеров это держат. Общее для Codex и Antigravity:

- **Сбой хука — отказ.** `brain hook` запускает адаптер под жёстким дедлайном ниже таймаута клиента; падение, таймаут
  или ответ не той формы на pre-событии становятся явным отказом клиенту, а не пропуском.
- **Код чекаута в хуке не исполняется.** Хук работает вне песочницы клиента, поэтому проверки, которые запускают код
  репозитория (`.claude/check.sh`, TypeScript проекта, тесты контура), для них выключены; `git` в хуках читает без
  fsmonitor, внешнего diff и textconv.
- **Свои предохранители агент не снимает.** `owner-files` отбивает запись в `~/.codex/hooks.json`,
  `~/.codex/brain.config.toml`, `~/.gemini/config/hooks.json`, `.agents/hooks.json` и `brain.config.json`.
- **Граница Codex:** хуку не передаётся рабочий каталог команды, поэтому относительные пути в ней судятся от каталога
  сессии; git и glab обязаны называть каталог явно (`cd /абс/путь && …`, `git -C`).

## Локальная модель

`brain local` поднимает сервер модели (если задан `local.serve`), запускает агента на `127.0.0.1:8091` и открывает
чат по ссылке с токеном (`…/#token=…`, она же печатается в терминале; новая вкладка — той же ссылкой). Модель — любая за OpenAI-совместимым API (`mlx_lm.server`, llama.cpp, Ollama); по умолчанию
`http://127.0.0.1:8080/v1`. Режимы — переключатель в окне:

- **Авто** (по умолчанию) — модель сама решает: ответить из знаний или работать в репозитории через инструменты до
  `finish`. Человека не спрашивают: недоказанное гейтом (`ask`/`unknown`) — отказ, как в авто-режиме Claude Code.
- **Агент** — то же, но вопрос гейта приходит тебе кнопками «Разрешить / Отклонить».
- **Чат** — разговор без инструментов.

Доказанное нарушение отбивается в любом режиме; задача не закрыта, пока Stop-гейты её не отпустили (находка сверки
возвращается модели). В окне видно каждый шаг: время модели, токены промпта и сколько из них взято из кеша, вызов,
вердикт гейта, вывод, итог.

**Контекстное окно.** Бюджет — `--context` (по умолчанию 24K токенов; на маленьком Mac узкое место — скорость чтения
промпта, а не размер окна). История дописывается без правок, чтобы сервер переиспользовал кеш промпта; при 85%
бюджета старый вывод инструментов укорачивается, затем старые ходы удаляются целиком (вызов вместе с ответом) с
заметкой, что было. Системный промпт и задача не трогаются никогда. Вывод одного инструмента — до 6000 знаков.

**Безопасность.** Сервер слушает только `127.0.0.1`, проверяет `Host` (DNS rebinding) и `Origin`, запрещает встраивание
во фрейм. Токен приходит в фрагменте ссылки и в самой странице не лежит: процесс, который откроет страницу, токена не
получит. Вопрос гейта принимается только по идентификатору, который придумал сервер, — модель не может ответить на
свой же вызов. После каждой команды её группа процессов убивается (фоновый хвост не переживает вызов), окружение
команды — разрешённый список (без `SSH_AUTH_SOCK`, DSN и токенов; добавить — `envKeep`). Файловые инструменты работают
с реальным путём внутри репозитория, ссылку последним компонентом не принимают и пишут с `O_NOFOLLOW`.

Это не песочница: команды модели выполняются от твоего пользователя, границу держат гейты — как у остальных
исполнителей. Процесс, запущенный через `setsid`, группу покидает; для недоверенной модели нужен отдельный
пользователь или контейнер.

## Конфиг площадки

Всё, что принадлежит одной машине и одной организации, живёт в конфиге, а не в коде. Действует первый найденный:
`CLAUDE_HARNESS_CONFIG` → `~/.claude/harness.config.json` → `harness.config.json` в корне чекаута. Образец —
`harness/harness.config.example.json`, контракт — `harness/src/config.ts`.

| Поле | Без конфига |
|---|---|
| `protectedBranches` | `main` — прямой push и MR только с `release/*` либо `hotfix/*` |
| `ownerHosts` | ни один хост не считается git компании — `owner-actions` судит только `glab` и явные API-вызовы |
| `shellPaths`, `freshness` | `git-freshness` ничего не смотрит |
| `dataBoundary.configTables` | ни одна таблица прода не считается конфигурацией — строки прода только бизнес-данные |
| `workDocs` | напоминание о work-doc молчит |

Файл есть, но не читается — это `problem`: `pre-push-guard` отвечает `unknown`, `owner-actions` — `deny` на push,
теги, `glab` и API, пока конфиг не починен. Прод-каналы Postgres гейт `data-boundary` узнаёт по имени обёртки
`mcp-pg-<канал>-prod` — соглашение пресета `postgres-k8s`.

Настройки исполнителей — `brain.config.json` (образец `brain.config.example.json`): `mcpAllowed`, `envKeep`, `local`.

## Границы

- Контур проверяет то, что видит в рабочем дереве и в аргументах команд. Инструменты MCP гейты не судят — поэтому
  исполнителям вне Claude доступны только серверы из `mcpAllowed`.
- Хуки Codex и Antigravity срабатывают только после review/trust в клиенте; файл хуков на диске сам по себе ничего не
  блокирует. Хуки ставятся на пользователя: строгая таблица инструментов действует и в сессиях Codex/Antigravity,
  запущенных не через `brain`.
- Адаптер Antigravity написан по документации (сверено 25.10.2026), живой сессией agy не проверен; инструмент MCP
  `call_mcp_tool` и его аргументы документацией не описаны — без совпадения адаптер отказывает.
- Причины отказов написаны по-русски.
